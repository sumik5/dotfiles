# Generate User Story Command

Webアプリケーションのコードを分析し、ユーザーストーリードキュメント（`docs/user-story.md`）とE2Eテストケースドキュメント（`docs/e2e.md`）を作成または更新する。

## 前提条件

- プロジェクトのルートディレクトリで実行すること
- Webアプリケーションのプロジェクトであること（Next.js、React、Express等）

## 手順

### 1. 既存ドキュメントの確認

- `docs/user-story.md` が存在する場合: 読み込んで既存のユーザーストーリーをベースに更新
- `docs/e2e.md` が存在する場合: 読み込んで既存のE2Eテストケースをベースに更新
- 存在しない場合: 一から作成

### 2. コードベース分析

以下の情報を収集する:

1. **プロジェクト構造**: ディレクトリ構造（`app/`, `pages/`, `src/`, `components/` 等）、ルーティング構造
2. **認証・認可**: 認証機能の有無（Keycloak、NextAuth、Firebase Auth等）、ユーザーロールやペルソナ
3. **主要機能**: ページやコンポーネントから主要な機能を抽出、APIエンドポイント、フォーム・リスト・詳細ページ
4. **データフロー**: DBスキーマ（Prisma schema等）、APIルート、状態管理（Zustand、Redux等）

### 3. ユーザーストーリードキュメント作成（`docs/user-story.md`）

以下の構造でドキュメントを作成:

#### 必須セクション

1. **ユーザーペルソナ**: 主要なユーザーロール（管理者、一般ユーザー、ゲスト等）、各ペルソナの役割・認証方法・主な活動
2. **主要なユーザーストーリー**: 各ペルソナごとに以下のフォーマットで作成:
   ```
   #### US-[ペルソナ略称][番号]: [ストーリータイトル]

   **As a** [ユーザーロール]
   **I want to** [実現したいこと]
   **So that** [得られる価値・理由]

   **受入基準**:
   - [具体的な基準1]
   - [具体的な基準2]
   ```
3. **ユーザーフロー図**: Mermaid記法でフローチャート（各ペルソナごと + 全体フロー）
4. **画面遷移フロー**: ページパス・説明・遷移先・遷移条件を表形式 + Mermaid遷移図
5. **データフロー**: 状態遷移図（stateDiagram-v2）、データモデル関係（erDiagram）、シーケンス図
6. **非機能要件**: セキュリティ、パフォーマンス、可用性、保守性
7. **今後の拡張予定**: 実装予定の機能やTODO項目

### 4. E2Eテストケースドキュメント作成（`docs/e2e.md`）

ユーザーストーリーに基づいてE2Eテストケースを作成:

#### 必須セクション

1. **テスト戦略**: 目的・スコープ・使用ツール・テスト環境
2. **テストケース一覧**: 各ユーザーストーリーに対応するテストケースを以下のフォーマットで作成:
   ```
   ### TC-[ペルソナ略称][番号]: [テストケース名]

   **対応ユーザーストーリー**: US-[XX]

   **前提条件**:
   - [前提条件1]

   **テストステップ**:
   1. [ステップ1]
   2. [ステップ2]

   **期待結果**:
   - [期待される結果1]

   **優先度**: High/Medium/Low
   ```
3. **クリティカルパステスト**: 最も重要なユーザーフロー、必ず成功すべきテストケース
4. **エッジケースとエラーハンドリング**: 異常系のテストケース
5. **パフォーマンステスト**: 応答時間、大量データでの動作確認
6. **テスト実行計画**: CI/CD自動実行、手動テスト項目、カバレッジ目標

### 5. 出力とフィードバック

1. `docs/user-story.md` を作成または更新
2. `docs/e2e.md` を作成または更新
3. ユーザーに以下を報告:
   - 特定したペルソナ数
   - 作成したユーザーストーリー数
   - 作成したE2Eテストケース数
   - 主要な機能の要約

## 注意事項

- 既存ファイルがある場合は内容を尊重し、不足部分を追加する形で更新
- コードから推測できない部分は合理的な仮定を記述し、コメントで明示
- Mermaid図は正確な記法を使用
- ユーザーストーリーは具体的で測定可能な受入基準を含める
- E2Eテストケースは実装可能な具体的なステップを記述
